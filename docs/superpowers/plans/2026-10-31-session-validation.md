# План изменения проверки сессии

**Основание:** `docs/superpowers/specs/2026-10-31-session-validation-design.md`.

Scope — мобильное приложение и PWA. Срок сессии меняется отдельно на стороне бэкенда.

1. Добавить `services/api/session-validation.ts`: общий предел 8000 мс, максимум две попытки, задержка 500 мс, таймаут попытки до 4000 мс и отмена через AbortController. Подключить только в `VisitControlApiClient.getMe`.
2. Проверить через настоящий API-клиент и управляемый транспорт: успех, повтор после временной ошибки, отсутствие повторов 401/403, зависший запрос, поздний ответ, ограниченный остаток бюджета, сохранение токена и очистку таймеров. Запустить связанные тесты, затем весь набор, типы и web-сборку.
3. Провести независимое ревью итоговых изменений приложения и устранить существенные замечания. Выпустить версию 1.0.8 через отдельный PR и публикацию статической PWA. Бэкенд не менять.

Особое внимание: автоматические повторы после истечения бюджета не отправляют запросов; сетевая ошибка не стирает токен; поздний ответ не открывает приложение. Срок JWT и ускорение обработки запроса сервером остаются вне этой небольшой правки.

## Результат

- Реализация и независимое ревью завершены; выпуск 1.0.8 подготовлен отдельно от бэкенда.
- Независимое ревью выявило P2: успешный ответ мог обогнать просроченный таймер после приостановки JS. Регрессионный тест сначала воспроизвёл ошибку, затем прошёл после проверки истёкшего времени перед возвратом профиля.
- Финальная проверка: 77 наборов / 507 тестов прошли, `npm run typecheck` и `npm run build:web` прошли. В изменённых файлах eslint ошибок нет; у прежнего импорта ApiResponse в visit-control-api.ts остаётся существовавшее предупреждение о неиспользовании.
- На физическом телефоне не проверялось. Срок сессии не изменяется этим релизом.
