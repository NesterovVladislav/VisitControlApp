## Недавние изменения
<!-- Что было сделано недавно -->
- Изменён текст на главном экране на "Привет мир"
- Реализован экран регистрации по `docs/registration-screen.md`: `app/register.tsx`, `components/registration-sent.tsx`, slice/saga `registration`, маски и валидация в `utils/`, компоненты `form-field`, `segmented-control`, `checkbox-row`. Пароль не вводится — приходит письмом после подтверждения администратором
- Роль и дети в заявке на регистрацию (`docs/registration-screen.md`, «Роль и дети»; `docs/admin-screens.md`, «Роль и дети в заявке»): заявитель — родитель или сотрудник, родитель указывает детей (`components/child-form-card.tsx`). Администратор при подтверждении меняет роль и по каждому ребёнку решает: создать, связать с ребёнком сада (`matches`) или не добавлять
- Выбор сада при регистрации (`docs/registration-screen.md`, «Выбор сада»): `components/organization-picker.tsx`, `components/organization-logo.tsx`, `selectOrganization` в slice `registration`, политика и заявка — по выбранному саду. При входе сад не выбирается, название сада из `GET /user` показывается в `components/profile-summary.tsx`
- Реализован экран «Мои дети» по `docs/children-screen.md` (`app/children.tsx`, slice/saga `children`) и реальный вход: `POST /token` → `GET /user`, токен в памяти (`services/auth/auth-token.ts`), Bearer и выход по 401 в `visit-control-api.ts`. SecureStore и восстановление сессии ещё не сделаны
- Каркас раздела администратора по `docs/admin-screens.md`: `app/(admin)/` с пятью вкладками (пока заглушки `components/admin-placeholder.tsx`), переключение режимов `state.auth.mode` / `switchMode`: «Ещё» → «Режим родителя», в «Мои дети» меню «⋯» → «Режим администратора». Маршрут после входа выбирается по роли и режиму в `app/auth.tsx`
- Вкладка «Посещение» администратора: `app/(admin)/visits/index.tsx`, slice/saga `visits` (`GET /group/children/present`, `GET /visit/list` с подгрузкой страниц), `utils/plural.ts`, `utils/visit-dates.ts`. Для админки пока тот же паттерн slice + saga, RTK Query не вводили
- Вкладка «Заявки» администратора: `app/(admin)/requests/` (свой Stack, список + `[id]`), slice/saga `requests`, значок с числом заявок в `app/(admin)/_layout.tsx`. Подтверждение, отказ с причиной, повторная отправка пароля
- Профиль и смена пароля по `docs/profile-screen.md`: `app/profile/index.tsx` (данные только для чтения), `app/profile/password.tsx` (`PATCH /user/password`), slice/saga `profile`, `auth/userRefreshed`. Вход — карточка в «Ещё» и «⋯» в «Мои дети». **Личные данные пользователь сам не меняет: только через заявку, которую подтверждает администратор** (бэкенда для заявок пока нет)
- «Посещение» → «Кто в саду»: выбор филиала, затем дети по группам (`app/(admin)/visits/_layout.tsx`, `branch/[id].tsx`, `utils/presence.ts`). Один запрос `GET /group/presence` без фильтра + `GET /branch/list`, разбивка по филиалам на клиенте
- Роль сотрудника `EMPLOYEE` (бэкенд: миграция `2026-09-28-employee-role.xml`, право `PRESENCE_READ`; приложение: `isStaffRole`). Сотрудник видит весь сад (вкладки «Посещение» и «Ещё»), не создаёт людей и не одобряет заявки, **может быть родителем** — переключение режимов как у администратора
- Вкладка «Люди» (`app/(admin)/people/index.tsx`, slice/saga `people`) на `GET /user/people` бэкенда: дети/родители/сотрудники, поиск с задержкой, фильтр детей по группе, постраничная подгрузка. Карточек и создания людей пока нет
- Пустые группы и состав группы: в «Посещении» видны все группы (без детей — «Детей пока нет»), у администратора «Изменить» → `app/(admin)/visits/group-members.tsx` (slice/saga `group-membership`): добавить, перевести, убрать. Бэкенд: `PUT` / `DELETE /group/{key}/children/{child_key}` (`USER_WRITE`). **Ребёнок в одной группе**: добавление из другой = перевод с подтверждением. **Убрать — только кнопкой «Убрать» и диалогом подтверждения**, строка ребёнка группы не нажимается
- Вкладка «Сад» сделана по `docs/garden-screen.md`: `app/(admin)/garden/` (филиалы → филиал → группа «Дети · Родители», «Дети без группы», диалог названия, «Состав группы» — общий `components/group-members-screen.tsx`), slice/saga `garden` и `group-people`, шторка `components/option-sheet.tsx`. Бэкенд: `POST/PUT/DELETE /group` (`BRANCH_WRITE`), 409 `NAME_TAKEN`/`BRANCH_NOT_EMPTY`/`GROUP_NOT_EMPTY`, родители группы в `/user/people`. Удаляются только пустые филиалы и группы
- «Журнал» — по дням → группам → по строке на ребёнка (приход → уход, кто привёл и забрал), `utils/journal.ts`. Бэкенд отдаёт в `/visit/list` нынешнюю группу ребёнка (`group`)
- Светлая / тёмная тема: выбор в «Профиле» → «Оформление», все экраны на палитре `constants/palette.ts` + `makeStyles` (`hooks/use-palette.ts`), см. «Стилизация» в systemPatterns
- Доверенные лица (кто ещё может забрать ребёнка) проработаны в `docs/trusted-pickup.md` (только дока): контакт без аккаунта + доверенность на 1–31 день, код + паспорт, отдаёт сотрудник. Найдена дыра: любой родитель может привязать себя к любому ребёнку через `POST /child-representative`
- Адрес бэкенда: `http://93.77.168.178/api` (через Caddy, порт 80; 8080 наружу закрыт)
